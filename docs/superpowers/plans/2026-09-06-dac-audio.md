# DAC Audio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stream 16-bit stereo audio out of the two internal DACs, behind an `AudioSink` interface that the existing I2S library also implements.

**Architecture:** TIM6's update event drives TRGO, which triggers both DAC channels together and raises DMAMUX request 103; DMA1 channel 1 moves one 32-bit word per frame from a circular ring into `DAC->RD12BDHR`, the dual holding register that carries both channels. A sketch only keeps the ring topped up. `AudioSink` is a small frame-oriented interface in the core so the eventual ESP8266Audio port writes one adapter rather than one per output.

**Tech Stack:** `cores/ch32h4/ch32h4_timer.{h,c}` (claim/release, input clock), `ch32h4_dac.{h,c}`, the vendor SDK's `ch32h417_dac.h`/`_dma.h`/`_tim.h`, the existing `libraries/I2S`, and the pytest hardware harness in `tests/hw`.

**Spec:** `docs/superpowers/specs/2026-09-06-dac-audio-design.md`

## Global Constraints

- **Nothing makes an audible sound by default.** There is an amplifier and a speaker wired to I2S instance 0 on this bench. Tests write mid-scale or measure timing; none plays audible content. If an audible check is ever wanted it happens only on request and at about 10% amplitude.
- Sample rate range: **1000 to 192000 Hz** inclusive. `begin()` returns false outside it.
- Ring default **4096 frames** (16 KB, 93 ms at 44.1 kHz), minimum **256 frames**.
- Silence is **`0x08000800`** — mid-scale on both channels.
- `AudioSink` frames are **16-bit signed**, stereo, interleaved.
- DAC1 = PA4 = left, DAC2 = PA5 = right. Fixed pins, no mux.
- **TIM6** and **DMA1 channel 1**. Both verified free: Tone/analogWrite/Servo hold TIM1/2/8; SPI holds DMA 2/3, I2S 4/5, ADCInput 7.
- **Timer clock is `ch32h4_timer_input_clock(6)`, never `SystemCoreClock`.** Timers divide HCLK; `SystemCoreClock` is 4x that on the V5F. MicroPython's port had every rate come out exactly 4x too slow from this.
- **Only DAC channel 1's DMA is enabled.** In dual mode its single request lands in both holding registers; enabling channel 2's as well fetches a second word per frame and drains the ring twice as fast.
- New timer owners are **appended** to the enum in `ch32h4_timer.h`, never inserted — the values are compared across separately compiled libraries.
- Commit messages end with `Co-Authored-By: Claude Opus 5 <noreply@anthropic.com>`.
- Hardware tests use the pinned wlink at `tools/bin/wlink.exe` (0.1.2). PlatformIO's `tool-wlink` is 0.1.1 and reports "Probe is not attached to an MCU" on this part regardless of health.

```cpp
/* One audio output, whichever pins it comes out of.
 *
 * Implemented by DACAudio (the two internal 12-bit DACs) and by I2S. It exists
 * so that a producer -- a tone generator, a WAV reader, eventually an
 * ESP8266Audio decoder -- can be written once against "somewhere to put
 * frames" rather than once per output.
 *
 * DELIBERATELY NOT ESP8266Audio's AudioOutput. That interface carries
 * SetGain, SetBitsPerSample and SetChannels, decisions whose only consumer
 * does not exist in this core yet, and fixing an interface before its consumer
 * arrives is how it ends up wrong. This says only what the two outputs here
 * genuinely share; the ESP8266Audio port adds an adapter over it, once.
 *
 * NO GAIN CONTROL, for the same reason a mixer has one fader per channel and
 * not two: scaling belongs to whatever produces the samples, and a sink that
 * also attenuates invites two volume controls in series and a quiet bug.
 *
 * FRAMES ARE 16-BIT SIGNED STEREO, interleaved. That is what decoders produce.
 * An implementation whose hardware wants something else converts internally --
 * I2S in 32-bit mode shifts left by 16, the DACs shift right by 4 -- rather
 * than the interface growing a width parameter for a choice only one of them
 * has.
 *
 * NOTHING HERE BLOCKS. A sink that waits inside a producer's callback is how
 * a stream stutters; a caller that wants to wait does so on availableFrames().
 */
#pragma once

#include <stddef.h>
#include <stdint.h>

class AudioSink {
public:
    virtual ~AudioSink() { }

    /* Start the output at `sampleRate` Hz. False if the rate is out of range,
       a resource is already held by something else, or it is already running.

       uint32_t RATHER THAN long, and I2S::begin(long) changes to match. The
       two cannot coexist: `begin(44100)` passes an int, which converts to
       long and to uint32_t equally well, so declaring both makes every
       existing call ambiguous and stops the library compiling. Narrowing the
       existing one is source-compatible for every caller that is not passing
       a negative rate, which begin() rejected anyway. */
    virtual bool begin(uint32_t sampleRate) = 0;

    /* Stop, release the hardware, and leave the output at rest.

       RETURNS bool, ONLY because I2S::end() already does and C++ will not
       overload on return type -- a `void end()` here would collide with it
       and neither could be renamed without breaking sketches. Callers may
       ignore it. */
    virtual bool end() = 0;

    virtual bool running() const = 0;

    /* The rate the output is ACTUALLY running at, which is not always the one
       asked for: I2S divides by an integer with one half-step, so 44100 comes
       back as 44117. A sketch generating a tone needs the real number. */
    virtual uint32_t sampleRate() const = 0;

    /* One stereo frame. A mono sink duplicates. Returns 1 if it was queued,
       0 if there was no room -- this does not wait. */
    virtual size_t writeFrame(int16_t left, int16_t right) = 0;

    /* Interleaved stereo frames. Returns how many were accepted, which may be
       fewer than offered and may be zero. */
    virtual size_t writeFrames(const int16_t *interleaved, size_t frames) = 0;

    /* Frames that can be accepted right now without waiting. */
    virtual size_t availableFrames() = 0;

    /* Frames the hardware wanted and did not have. Zero until something has
       been queued, because an empty buffer before playback starts is normal
       rather than a fault. */
    virtual uint32_t underruns() const = 0;
};
```

```cpp
     *
     * Nearly all of this the class already had. begin(), end() and running()
     * satisfy the interface as they stand; only the four below are new, and
     * none of them changes what an existing method does. */
    uint32_t sampleRate() const override {
        /* The achieved rate, not the requested one -- see AudioSink.h. Before
           begin() there is no achieved rate, so the request is the best
           answer available. */
        return _actual_rate ? _actual_rate : _rate;
    }

    size_t writeFrame(int16_t left, int16_t right) override;
    size_t writeFrames(const int16_t *interleaved, size_t frames) override;
    size_t availableFrames() override;

    /* The counter that getUnderflows() reports, read WITHOUT clearing it.
       getUnderflows() is destructive and cannot be called from a const
       method; more to the point, a caller polling underruns() must not
       silently consume the count that a sketch's own getUnderflows() is
       there to read. */
    uint32_t underruns() const override { return _underflows; }

    /* Bytes in one stereo frame: two samples of the configured width. 4 at
       16 bits, 8 at 32. availableForWrite() is in bytes, so anything
       converting between the two needs this. */
    size_t frameBytes() const { return 2u * (_bits / 8u); }
```

No new member is needed. `_underflows` already exists, already counts, and is

- [ ] **Step 6: Implement the three real methods**

In `libraries/I2S/src/I2S.cpp`:

```cpp
size_t I2S::availableFrames() {
    const size_t fb = frameBytes();
    return fb ? (size_t)availableForWrite() / fb : 0;
}

size_t I2S::writeFrame(int16_t left, int16_t right) {
    if (!_running || _rx) {
        return 0;
    }
    /* Checked first, and deliberately: the write() overloads below wait up to
     * the stream timeout for room, and AudioSink says nothing blocks. Room for
     * a whole frame means neither of them can reach that wait. A sink that
     * stalls inside a producer's callback is how a stream stutters. */
    if ((size_t)availableForWrite() < frameBytes()) {
        return 0;
    }
    /* Mono duplication is left to the existing overloads, which already do it
     * -- doing it here as well would be a second copy of the rule to keep in
     * step with the first. */
    if (_bits == 32) {
        /* AudioSink frames are 16-bit; this port wants 32. Shift up rather
         * than sign-extend: the sample belongs in the high half, and the low
         * half is the fractional bits it does not have. */
        return write((int32_t)left << 16, (int32_t)right << 16) == 2 ? 1 : 0;
    }
    return write(left, right) == 2 ? 1 : 0;
}
```

Both `write(int16_t, int16_t)` and `write(int32_t, int32_t)` return a count of
**samples**, so a queued stereo frame is 2 — which is why the comparison is
against 2 and not against a byte count.

```cpp
size_t I2S::writeFrames(const int16_t *interleaved, size_t frames) {
    size_t done = 0;
    while (done < frames) {
        if (!writeFrame(interleaved[2 * done], interleaved[2 * done + 1])) {
            break;
        }
        done++;
    }
    return done;
}
```

```cpp
/* Streaming audio out of the two internal 12-bit DACs.
 *
 *     DACAudio dac;
 *     dac.begin(44100);
 *     dac.writeFrame(left, right);
 *
 * analogWrite() and ch32h4_dac_write() already drive these pins one sample at
 * a time, which is a control voltage. This is the streaming path: TIM6 paces
 * the conversions, DMA feeds them, and a sketch only keeps the ring topped up.
 *
 * THE PINS ARE FIXED: PA4 is DAC1 and left, PA5 is DAC2 and right. There is no
 * mux. Mono duplicates to both, so a mono source works with whichever pin
 * happens to be wired -- which does mean PA5 is not available as an
 * independent analogWrite output while this is running.
 *
 * THESE ARE RAW DAC PINS. There is no output buffer worth the name at audio
 * rates: feed them into a HIGH-IMPEDANCE input, with an RC low-pass on each to
 * remove the sample-rate staircase, and not into a speaker or a low-impedance
 * amplifier input directly. Without the filter the output is a 12-bit
 * staircase at the sample rate and sounds like it -- which is easily mistaken
 * for a fault in this driver.
 *
 * THE DMA NEVER STOPS while running. It circles the ring whether or not
 * anything has been queued, so what it plays when a producer falls behind is
 * whatever is in the ring. The unwritten part is kept filled with silence, so
 * that is heard as a gap rather than as the last 93 ms repeating.
 */
#pragma once

#include <Arduino.h>
#include <AudioSink.h>

class DACAudio : public AudioSink {
public:
    /* Frames, not bytes: one frame is four bytes, both channels. 4096 is
       93 ms at 44.1 kHz, enough that a slow network read or a flash write
       cannot be heard. */
    static const size_t DEFAULT_FRAMES = 4096;
    static const size_t MIN_FRAMES = 256;
    static const uint32_t RATE_MIN = 1000;
    static const uint32_t RATE_MAX = 192000;

    DACAudio() { }
    ~DACAudio() { end(); }

    /* Before begin(); ignored after. False if below MIN_FRAMES. */
    bool setBuffer(size_t frames);

    /* Mono duplicates each sample to both pins. Changeable while running. */
    bool setStereo(bool stereo = true);
    bool setMono(bool mono = true) { return setStereo(!mono); }

    bool begin(uint32_t sampleRate) override;
    bool end() override;
    bool running() const override { return _running; }
    uint32_t sampleRate() const override { return _rate; }

    size_t writeFrame(int16_t left, int16_t right) override;
    size_t writeFrames(const int16_t *interleaved, size_t frames) override;
    size_t availableFrames() override;
    uint32_t underruns() const override { return _underruns; }

    /* The ring index the DMA is reading. Exposed because it is the only
       honest way to measure the real sample clock: the DMA consumes exactly
       one word per conversion, so watching this advance over a known interval
       measures the rate the hardware is actually running at. */
    size_t dmaPosition() const;

    size_t bufferFrames() const { return _frames; }

private:
    size_t freeFrames() const;
    void blankFree();
    bool startTimer(uint32_t rate);
    void noteUnderruns();

    uint32_t *_ring = nullptr;
    size_t _frames = DEFAULT_FRAMES;
    size_t _wr = 0;
    uint32_t _rate = 0;
    uint32_t _underruns = 0;
    bool _stereo = true;
    bool _running = false;

    /* For spotting an underrun between two writes; see the note in
       noteUnderruns(). */
    bool _primed = false;
    size_t _queuedAtWrite = 0;
    uint32_t _lastWriteUs = 0;
};
```

```python
"""Streaming audio out of the two internal DACs.

NOTHING HERE MAKES A SOUND. Every test writes mid-scale or measures timing;
there is an amplifier and a speaker on this bench and none of these reach it.

The sample clock is the thing worth measuring most carefully, because it is
the one number a listener would notice being wrong and the one a compile
cannot check: the DMA consumes exactly one word per conversion, so watching
its counter advance over a known interval measures the rate the hardware is
really running at.
"""
import pytest

from conftest import kv


@pytest.fixture(scope="module")
def dac(dac_board):
    return dac_board


@pytest.mark.parametrize("rate", [8000, 44100, 96000])
def test_the_sample_clock_is_the_requested_rate(dac, rate):
    """Within 1%. A timer clocked from SystemCoreClock rather than HCLK comes
    out exactly 4x wrong on this part, which is the mistake this catches."""
    r = kv(dac.command(f"rate {rate}", timeout=20))
    assert r["begun"] == 1, r.raw
    m = kv(dac.command("measure 200", timeout=20))
    measured = m["measured_hz"]
    assert abs(measured - rate) / rate < 0.01, (
        f"asked for {rate} Hz, measured {measured} Hz")


def test_begin_refuses_rates_outside_the_range(dac):
    assert kv(dac.command("rate 999", timeout=20))["begun"] == 0
    assert kv(dac.command("rate 192001", timeout=20))["begun"] == 0
    assert kv(dac.command("rate 44100", timeout=20))["begun"] == 1


def test_a_second_begin_without_end_is_refused(dac):
    assert kv(dac.command("rate 44100", timeout=20))["begun"] == 1
    assert kv(dac.command("beginagain", timeout=20))["begun"] == 0


def test_end_releases_the_timer_so_begin_works_again(dac):
    dac.command("stop", timeout=20)
    r = kv(dac.command("timerowner", timeout=10))
    assert r["owner"] == "free", r.raw
    assert kv(dac.command("rate 44100", timeout=20))["begun"] == 1
    r = kv(dac.command("timerowner", timeout=10))
    assert r["owner"] == "audio", r.raw
```

```cpp
bool DACAudio::begin(uint32_t sampleRate) {
    if (_running) {
        return false;
    }
    if (sampleRate < RATE_MIN || sampleRate > RATE_MAX) {
        return false;
    }
    if (!ch32h4_timer_claim(DAC_TIMER_ID, CH32H4_TIMER_AUDIO)) {
        return false;
    }

    _ring = (uint32_t *)malloc(_frames * sizeof(uint32_t));
    if (!_ring) {
        ch32h4_timer_release(DAC_TIMER_ID, CH32H4_TIMER_AUDIO);
        return false;
    }
    for (size_t i = 0; i < _frames; i++) {
        _ring[i] = DAC_SILENCE;
    }
    _rate = sampleRate;
    _underruns = 0;
    _primed = false;

    /* Analog mode: the pad's digital input buffer and both drivers have to be
       out of the way before the DAC drives it. */
    RCC_HB2PeriphClockCmd(RCC_HB2Periph_GPIOA, ENABLE);
    GPIO_InitTypeDef gpio = { 0 };
    gpio.GPIO_Pin = GPIO_Pin_4 | GPIO_Pin_5;
    gpio.GPIO_Mode = GPIO_Mode_AIN;
    GPIO_Init(GPIOA, &gpio);

    RCC_HB1PeriphClockCmd(RCC_HB1Periph_DAC, ENABLE);
    RCC_HBPeriphClockCmd(RCC_HBPeriph_DMA1, ENABLE);

    DAC_InitTypeDef dac = { 0 };
    dac.DAC_Trigger = DAC_Trigger_T6_TRGO;
    dac.DAC_WaveGeneration = DAC_WaveGeneration_None;
    dac.DAC_OutputBuffer = DAC_OutputBuffer_Enable;
    DAC_Init(DAC_Channel_1, &dac);
    DAC_Init(DAC_Channel_2, &dac);

    DMA_DeInit(DAC_DMA_CHANNEL);
    DMA_InitTypeDef dma = { 0 };
    dma.DMA_PeripheralBaseAddr = (uint32_t)&DAC->RD12BDHR;
    dma.DMA_Memory0BaseAddr = (uint32_t)_ring;
    dma.DMA_DIR = DMA_DIR_PeripheralDST;
    dma.DMA_BufferSize = (uint16_t)_frames;
    dma.DMA_PeripheralInc = DMA_PeripheralInc_Disable;
    dma.DMA_MemoryInc = DMA_MemoryInc_Enable;
    dma.DMA_PeripheralDataSize = DMA_PeripheralDataSize_Word;
    dma.DMA_MemoryDataSize = DMA_MemoryDataSize_Word;
    dma.DMA_Mode = DMA_Mode_Circular;
    dma.DMA_Priority = DMA_Priority_VeryHigh;
    dma.DMA_M2M = DMA_M2M_Disable;
    DMA_Init(DAC_DMA_CHANNEL, &dma);
    DMA_MuxChannelConfig(DAC_DMA_MUX_CHANNEL, DAC_DMA_REQ_DAC1);
    DMA_Cmd(DAC_DMA_CHANNEL, ENABLE);

    /* ONLY CHANNEL 1's DMA. In dual mode its single request moves one word
     * into RD12BDHR, which lands in both channels' holding registers.
     * Enabling channel 2's as well fetches a second word per frame and drains
     * the ring at twice the rate -- which sounds like the sample rate being
     * double what was asked for, not like a DMA misconfiguration. */
    DAC_DMACmd(DAC_Channel_1, ENABLE);
    DAC_Cmd(DAC_Channel_1, ENABLE);
    DAC_Cmd(DAC_Channel_2, ENABLE);

    if (!startTimer(sampleRate)) {
        end();
        return false;
    }

    /* Start writing where the DMA is reading, not at word 0.
     *
     * The ring is pre-filled with silence and the DMA starts consuming it the
     * instant it is enabled, so by the time a sketch gets a turn the reader
     * has already moved past word 0. Leaving the writer behind it would report
     * an almost-full ring and make the first write wait a whole buffer period
     * -- 93 ms at the default size -- before one real sample reached the pins. */
    _wr = dmaPosition();
    _running = true;
    return true;
}
```

```cpp
bool DACAudio::startTimer(uint32_t rate) {
    ch32h4_timer_clock_enable(DAC_TIMER_ID);
    ch32h4_timer_reset(DAC_TIMER_ID);

    /* ch32h4_timer_input_clock(), NOT SystemCoreClock. Timers divide HCLK on
     * this part and the V5F runs at four times that, so SystemCoreClock makes
     * every rate come out exactly 4x too slow -- which MicroPython's port hit
     * and this core's timer header warns about in as many words. */
    const uint32_t clk = ch32h4_timer_input_clock(DAC_TIMER_ID);
    if (!clk) {
        return false;
    }
    uint32_t psc = 0;
    while ((clk / (psc + 1)) / rate > 0xFFFF) {
        psc++;
    }
    uint32_t period = (clk / (psc + 1) + rate / 2) / rate;
    if (period < 2) {
        period = 2;
    }

    TIM_TimeBaseInitTypeDef tb = { 0 };
    tb.TIM_Prescaler = (uint16_t)psc;
    tb.TIM_CounterMode = TIM_CounterMode_Up;
    tb.TIM_Period = (uint16_t)(period - 1);
    tb.TIM_ClockDivision = TIM_CKD_DIV1;
    TIM_TimeBaseInit(TIM6, &tb);

    /* The update event drives TRGO, which is what the DAC trigger listens
       to. Without this the DACs are configured and never fire. */
    TIM_SelectOutputTrigger(TIM6, TIM_TRGOSource_Update);
    TIM_Cmd(TIM6, ENABLE);
    return true;
}
```

```cpp
size_t DACAudio::dmaPosition() const {
    /* CNTR counts down from `_frames` and reloads, so what has been consumed
       out of this pass is _frames - CNTR. */
    uint32_t left = DMA_GetCurrDataCounter(DAC_DMA_CHANNEL);
    if (left == 0 || left > _frames) {
        return 0;
    }
    return _frames - left;
}

size_t DACAudio::freeFrames() const {
    const size_t rd = dmaPosition();
    const size_t used = (_wr + _frames - rd) % _frames;
    /* One held back, so a full ring is distinguishable from an empty one. */
    return _frames - used - 1;
}

size_t DACAudio::availableFrames() {
    return _running ? freeFrames() : 0;
}

bool DACAudio::end() {
    if (!_running && !_ring) {
        return true;        /* already stopped; see AudioSink.h on the bool */
    }
    _running = false;
    TIM_Cmd(TIM6, DISABLE);
    DMA_Cmd(DAC_DMA_CHANNEL, DISABLE);
    DAC_DMACmd(DAC_Channel_1, DISABLE);

    /* Park both channels at mid-scale rather than at whatever sample the DMA
       stopped on, so switching off leaves no DC offset on the output. */
    DAC->RD12BDHR = DAC_SILENCE;
    DAC_Cmd(DAC_Channel_1, DISABLE);
    DAC_Cmd(DAC_Channel_2, DISABLE);

    ch32h4_timer_release(DAC_TIMER_ID, CH32H4_TIMER_AUDIO);
    free(_ring);
    _ring = nullptr;
    _rate = 0;
    return true;
}

bool DACAudio::setBuffer(size_t frames) {
    if (_running || frames < MIN_FRAMES) {
        return false;
    }
    _frames = frames;
    return true;
}

bool DACAudio::setStereo(bool stereo) {
    _stereo = stereo;
    return true;
}
```

```cpp
/* Leave the unwritten part of the ring holding silence.
 *
 * The DMA never stops. It circles the ring whether or not anything has been
 * queued, so whatever sits ahead of the write pointer is what gets played when
 * the producer falls behind. Left alone that is the previous pass's audio, and
 * a stalled stream is then heard as the last fraction of a second repeating --
 * which sounds like a decoder fault rather than what it is. Filled with
 * silence it is heard as a gap: unmistakably a gap, and less alarming.
 *
 * Only the free region is touched, so this races neither the DMA reading the
 * queued frames nor a later write laying real frames over the same silence.
 * The DMA advancing during the loop only frees more words, so at worst a few
 * are left holding stale audio until the next call. */
void DACAudio::blankFree() {
    size_t space = freeFrames();
    size_t pos = _wr;
    for (size_t i = 0; i < space; i++) {
        _ring[pos] = DAC_SILENCE;
        pos = (pos + 1 == _frames) ? 0 : pos + 1;
    }
}

/* Did the DMA run out of queued frames since the last write?
 *
 * NOT ANSWERABLE FROM THE RING POINTERS. The moment the read pointer passes
 * the write pointer their difference wraps, so an empty ring and a full one
 * are the same reading a few microseconds apart -- measured in the MicroPython
 * port, where checking for "everything free" caught nothing at all, because it
 * is true only for the instant the two are equal.
 *
 * The clock has no such ambiguity. The DMA consumes exactly `_rate` frames a
 * second whatever the producer is doing, so comparing elapsed time against
 * what was left queued says plainly whether it ran dry, and stays right
 * however long the gap was. */
void DACAudio::noteUnderruns() {
    if (_primed) {
        const uint32_t elapsed = micros() - _lastWriteUs;
        const uint64_t consumed = ((uint64_t)elapsed * _rate) / 1000000u;
        if (consumed > (uint64_t)_queuedAtWrite) {
            _underruns++;
        }
    }
}

size_t DACAudio::writeFrames(const int16_t *interleaved, size_t frames) {
    if (!_running || !interleaved) {
        return 0;
    }
    noteUnderruns();

    size_t done = 0;
    while (done < frames) {
        size_t space = freeFrames();
        if (space == 0) {
            break;      /* does not wait; see AudioSink.h */
        }
        size_t n = frames - done;
        if (n > space) {
            n = space;
        }
        for (size_t i = 0; i < n; i++) {
            int16_t l = interleaved[2 * (done + i)];
            int16_t r = _stereo ? interleaved[2 * (done + i) + 1] : l;
            /* Signed 16-bit to unsigned 12-bit: shift the range up by half
               scale, then drop the four low bits the DAC cannot represent. */
            const uint32_t lu = (uint32_t)(l + 32768) >> 4;
            const uint32_t ru = (uint32_t)(r + 32768) >> 4;
            _ring[_wr] = lu | (ru << 16);
            _wr = (_wr + 1 == _frames) ? 0 : _wr + 1;
        }
        done += n;
    }

    blankFree();
    _queuedAtWrite = _frames - freeFrames() - 1;
    _lastWriteUs = micros();
    _primed = true;
    return done;
}

size_t DACAudio::writeFrame(int16_t left, int16_t right) {
    const int16_t frame[2] = { left, right };
    return writeFrames(frame, 1);
}
```

```cpp
/*
   PlayTone - a sine wave out of the internal DACs.

   QUIET ON PURPOSE. AMPLITUDE is a tenth of full scale, because this is the
   first thing anyone runs and the first thing anyone runs should not be at
   full volume into whatever happens to be connected. Raise it once you know
   what is on the other end.

   WIRING. PA4 is left, PA5 is right, and they are raw DAC pins: put an RC
   low-pass on each -- 1 kOhm and 100 nF is a reasonable start, about 1.6 kHz
   -- and feed a HIGH-IMPEDANCE input such as a powered speaker's line in. Not
   a speaker directly: these pins cannot drive one, and trying is how a pin
   dies.

   Without the filter you hear the 12-bit staircase at the sample rate, which
   sounds like a fault in the driver and is not.

   Released to the public domain.
*/

#include <DACAudio.h>
#include <math.h>

DACAudio dac;

const uint32_t RATE = 44100;
const float FREQ = 440.0f;      /* concert A */
const float AMPLITUDE = 0.1f;   /* see above */

/* One period, generated once. Regenerating per frame would spend most of the
   sample budget in sinf(). */
const size_t TABLE = 100;       /* 44100 / 441 -- a whole number of periods */
int16_t table[TABLE];

void setup() {
    Serial.begin(115200);
    while (!Serial && millis() < 3000) {
        delay(10);
    }

    for (size_t i = 0; i < TABLE; i++) {
        const float phase = (2.0f * (float)M_PI * (float)i) / (float)TABLE;
        table[i] = (int16_t)(sinf(phase) * 32767.0f * AMPLITUDE);
    }

    if (!dac.begin(RATE)) {
        Serial.println("DACAudio.begin() failed -- is TIM6 taken, or the rate out of range?");
        return;
    }
    Serial.printf("Playing %.0f Hz at %.0f%% into PA4/PA5.\n",
                  (double)FREQ, (double)(AMPLITUDE * 100.0f));
}

void loop() {
    if (!dac.running()) {
        return;
    }
    /* Top the ring up with whatever room there is. The sink never blocks, so
       this returns promptly however busy the output is. */
    static size_t phase = 0;
    while (dac.availableFrames() > 0) {
        const int16_t s = table[phase];
        phase = (phase + 1 == TABLE) ? 0 : phase + 1;
        if (!dac.writeFrame(s, s)) {
            break;
        }
    }
}
```

## Self-review notes

Spec coverage: `AudioSink` and its no-gain/16-bit decisions → Task 1; the hardware chain, ring, rates and buffer → Task 2; silence, underruns, starvation → Task 3; examples, docs, regression → Task 4. The spec's six testing items map to `test_the_sample_clock_is_the_requested_rate`, `test_available_frames_falls_as_frames_are_queued`, the two underrun tests, `test_mono_reaches_both_channels`, `test_begin_refuses_rates_outside_the_range` plus `test_a_second_begin_without_end_is_refused`, and `test_end_releases_the_timer_so_begin_works_again`.

Type consistency: `AudioSink`'s eight methods are declared once in Task 1 Step 1 and implemented with the same signatures in Task 1 Steps 5–6 (I2S) and Task 2 Steps 1, 6 and Task 3 Step 3 (DACAudio). `dmaPosition()`, `bufferFrames()`, `freeFrames()`, `blankFree()` and `noteUnderruns()` are declared in Task 2 Step 1 and defined in Task 2 Step 6 and Task 3 Step 3.

**One thing caught while writing, and it would have failed on the bench:** the rate test measures how far the DMA advances over a window, but the ring wraps, so a window longer than the ring makes `moved` wrap and the measurement come out low. At 44.1 kHz a 200 ms window is 8820 frames against a 4096-frame ring — wrong. The windows are per-rate now: 200 ms at 8 kHz, 40 ms at 44.1 kHz, 20 ms at 96 kHz, each comfortably under 4096 frames.

**Two risks the implementer should carry:**

- **DMAMUX request 103** comes from MicroPython's port citing reference-manual table 10-2. It is the one number here nothing in this repo can check. If the DMA never advances, this is the first thing to doubt — `dmaPosition()` stuck at 0 with the timer running is exactly that symptom.
- **`DAC_OutputBuffer_Enable`** is what the MicroPython driver uses. `ch32h4_dac.c` notes the buffer costs about 5 mV of range at the bottom and gains rail-to-rail behaviour otherwise; the trade is fine for audio, but if the output looks clipped near zero this is the setting to look at.

## As built

Executed inline, 2026-09-06. Task 1 landed on its own; tasks 2 and 3 were
combined into one flash cycle because the implementation was a single file and
splitting the commit would have meant claiming a verification checkpoint that
never happened — the rate tests were still run in isolation first, which is
where the checkpoint's value actually was.

**Corrections made to this plan before executing it** (commit `0605c0f`), all
found by reading `libraries/I2S` rather than trusting the spec: `AudioSink::end()`
must return `bool`; `begin()` had to narrow rather than overload; I2S already
counted underruns; `sampleRate()` should report the achieved rate.

**Deviations made while executing:**

- `begin()` uses `ch32h4_pin_af()` and `ch32h4_clock_enable()` rather than the
  raw `GPIO_Init`/`RCC_*Cmd` calls this plan wrote. The core already owns that
  knowledge — why these pads must be analog, and that a clock enable has to be
  read back — and the plan had bypassed it. `begin()` also clears the
  single-shot path's started flag, which the plan missed entirely: without it
  an `analogWrite()` after `end()` writes to a disabled DAC and does nothing.
- `sinkfull` counts refusals across 200 attempts instead of timing one write.
  The DMA frees a frame every 22 us, so "fill, then time one write" can
  legitimately succeed and would have been flaky.
- The mono test asserts the exact 12-bit code, with a stereo counterpart. As
  planned it asserted only that both halves matched, which silence also
  satisfies — and silence was exactly what the first implementation produced.
- Four tests added beyond the plan to cover spec items it had dropped: the ring
  starts empty, free space recovers as the DMA drains, TIM6 is actually stopped
  (not merely unclaimed), and stereo keeps the channels apart.

**Two bugs found on hardware**, both in code this plan specified, and both now
in `docs/hazards.md`: ring-pointer accounting cannot distinguish an empty ring
from a full one against a free-running reader, and `blankFree()` refilling the
whole free region per write made the driver declare an underrun against itself.

**Risks resolved.** DMAMUX request 103 was correct — the measured rate confirms
it. `DAC_OutputBuffer_Enable` was already the right call: `hazards.md` records
that this silicon's buffer costs about one count, unlike STM32's.
